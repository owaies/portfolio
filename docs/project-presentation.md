# Project Presentation Guide

Project entries should help a visitor understand what was built, why it matters, and where the implementation can be inspected.

Use accurate titles, descriptions, technologies, categories, repository links, and deployment state from the actual project record.

Do not invent performance numbers, users, customers, awards, or deployment claims. If a project is local, present it as local. If it is deployed, verify the live URL before labeling it deployed.

Keep project descriptions concise on listing cards and reserve deeper implementation context for the project detail page.
